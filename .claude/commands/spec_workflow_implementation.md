## 实现阶段工作流程

### 第一步：全面理解规范文档
系统需要完整地阅读和理解以下文档：
- `<feature_name>_spec_context.md` - 开发上下文和代码基础设施
- `<feature_name>_spec_design.md` - 需求、概念层面设计和执行逻辑，最终实现的建议文件结构。

### 第二步：制定实现计划，并逐步实现
基于规范文档，系统应该：
1. 识别需要创建/修改的所有文件，确定实现的先后顺序和依赖关系
2. 参考`<feature_name>_spec_todo`,分段创建的任务列表（使用 TodoWrite 工具）
3. 参考 `<feature_name>_spec_code_snippets.md` 关键功能，步骤，特性的样板代码，确保实现精确符合规范文档中的设计描述。在实现过程中保持代码的可读性和可维护性。遵循项目现有的代码风格和最佳实践

### 第三步：验证和测试
- 按照规范文档中的 `<feature_name>_spec_review.md` 进行审核
- 进行基本的功能测试
- 确保实现符合所有设计要求
- 向用户报告实现结果和任何需要关注的问题

## 重要原则

### 严格遵循规范
- **不要偏离规范文档**：实现必须精确遵循已经审查通过的规范
- **优先使用文档中的示例**：规范文档中的代码片段是经过精心设计的
- **保持自包含**：如果发现需要规范文档之外的信息，先询问用户

### 渐进式实现
- **先结构后细节**：先搭建框架，再填充细节
- **小步快跑**：每次实现一小部分，及时提交代码
- **持续验证**：每个阶段都要验证实现是否符合规范

### 主动沟通
- **遇到决策点时询问用户**：不要擅自做主
- **报告进度**：定期向用户汇报实现进度
- **标记风险**：及时指出可能的技术风险或设计问题
