# 导入时环境变量异常问题报告

## 问题描述

项目中多个模块在 `import` 阶段（模块顶层代码执行时）就访问环境变量或创建外部连接。这导致：

1. **缺少环境变量时 import 直接抛异常**，无法进行局部导入测试
2. **import 时创建外部连接**（数据库、Redis、S3），即使只是想测试一个不相关功能也会触发连接

## 问题根因

`api/core/env_config.py` 在模块顶层实例化所有配置对象（第 278-286 行）。配置对象本身不会失败（字段都有默认值），但下游的常量模块在导入时立即访问这些配置并创建连接。

---

## 问题一：`JWT_SECRET_KEY` 未设置导致 import 异常

**文件：** `api/authentication/constant.py:17`

```python
JWT_SECRET_KEY = auth_config.jwt_secret_key.get_secret_value()
```

**触发链：**

```
import api.authentication.constant
  → auth_config.jwt_secret_key  (property getter)
    → self.jwt_secret_key_value is None  (未设 JWT_SECRET_KEY 环境变量)
      → raise ValueError("JWT_SECRET_KEY is not set")
```

**影响范围：** 任何直接或间接导入 `api.authentication` 的代码，包括：
- `api/authentication/utils.py`
- `api/authentication/__init__.py`
- `api/human_in_loop/ws_worker/ws_worker.py`
- `api/app/auth/token.py`

import api.user_pod_scheduler.constants

**影响范围：**

## 问题三：import 时创建 SQLAlchemy 引擎

**文件：** `api/sql_utils/constant.py:57-63`

```python
SQL_ENGINE = create_engine(sql_url)
ASYNC_SQL_ENGINE = create_async_engine(async_sql_url, **_ENGINE_KWARGS)
JUICE_FS_METADATA_SQLENGINE = create_engine(juice_fs_metadata_sql_url)
JUICE_FS_METADATA_ASYNC_SQLENGINE = create_async_engine(juice_fs_metadata_async_sql_url, ...)
```

**触发链：**

```
from api.sql_utils import ASYNC_SQL_ENGINE
  → api/sql_utils/__init__.py  (from .constant import SQL_ENGINE, ASYNC_SQL_ENGINE)
    → api/sql_utils/constant.py 模块顶层执行
      → create_engine(sql_url)           # 创建主 PostgreSQL 连接池
      → create_engine(juice_fs_metadata_sql_url)  # 创建 JuiceFS PostgreSQL 连接池
```

**特点：** 虽然不会因缺少环境变量抛异常（密码字段都有默认值），但 import 时就会创建 4 个数据库连接池。如果 `postgres` 主机不可达，首次使用时才会报错，但连接池对象已被创建。

**影响范围：** 17+ 个文件通过 `from api.sql_utils import ASYNC_SQL_ENGINE` 触发，几乎覆盖所有涉及数据库操作的业务模块。

## 问题四：import 时创建 S3 客户端并初始化存储桶

**文件：** `api/s3_FS/__init__.py:22-37, 61-62`

```python
S3_CLIENT = boto3.client("s3", endpoint_url=S3_ENDPOINT, ...)
JUICEFS_S3_CLIENT = boto3.client("s3", endpoint_url=JUICEFS_S3_ENDPOINT, ...)

# 模块顶层立即调用
setup_bucket(DEFAULT_BUCKET)
setup_bucket(USER_SPACE_BUCKET)
```

**触发链：**

```
from api.s3_FS import ...
  → api/s3_FS/__init__.py 模块顶层执行
    → boto3.client(...)          # 创建主 MinIO 客户端
    → boto3.client(...)          # 创建 JuiceFS MinIO 客户端
    → setup_bucket("default")    # 尝试创建存储桶（涉及网络请求）
    → setup_bucket("user-space") # 尝试创建存储桶（涉及网络请求）
```

**特点：** `setup_bucket()` 会发起实际的 HTTP 请求到 MinIO 端点。如果 MinIO 不可达，不会崩溃（被 try/except 捕获并记录错误日志），但会阻塞 import 过程并产生超时等待。

**影响范围：**
- `api/user_space/file_system/fs_utils/` 下所有文件
- `api/juiceFS/creator.py`
- `api/logger/exception_dump.py`
- `api/app/chunk/hierarchical_chunk.py`

## 问题五：import 时创建 Redis 客户端

**文件：** `api/redis/constants.py:3`

```python
CLIENT = Redis(host="redis", port=6379, protocol=3)
```

**触发链：**

```
from api.redis.constants import CLIENT
  → Redis(host="redis", port=6379, protocol=3)  # 创建 Redis 连接池对象
```

**特点：** `redis-py` 的 `Redis()` 构造函数本身不立即建立 TCP 连接，但会创建连接池配置。实际连接在首次命令时建立。不过这仍然意味着 import 时就绑定了 `redis:6379` 这个地址。

**影响范围：**
- `api/redis/__init__.py`
- `api/redis/distributed_lock.py`
- `api/system_notification/redis_ops.py`
- `api/system_notification/dual_write.py`
- `api/chat/streaming_processor.py`
- `api/chat/stream_listener.py`

## 问题汇总

| # | 文件 | 导入时行为 | 缺少环境变量时 | 外部不可达时 |
|---|------|-----------|--------------|-------------|
| 1 | `api/authentication/constant.py` | 访问 `JWT_SECRET_KEY` | **抛 ValueError 崩溃** | N/A |
| 2 | `api/user_pod_scheduler/constants.py` | 访问 `USER_POD_IMAGE` | **抛 ValueError 崩溃** | N/A |
| 3 | `api/sql_utils/constant.py` | 创建 4 个 DB 引擎 | 不崩溃（有默认值） | 延迟到使用时报错 |
| 4 | `api/s3_FS/__init__.py` | 创建 2 个 S3 客户端 + 初始化桶 | 不崩溃（有默认值） | import 时超时/日志报错 |
| 5 | `api/redis/constants.py` | 创建 Redis 客户端 | 不崩溃 | 延迟到使用时报错 |

## 受影响的环境变量清单

以下环境变量在模块导入时被访问，缺少时会导致 `ValueError`：

- **`JWT_SECRET_KEY`** — 被 `api/authentication/constant.py` 在 import 时访问
- **`USER_POD_IMAGE`** — 被 `api/user_pod_scheduler/constants.py` 在 import 时访问

以下环境变量在导入时通过默认值安全解析，但会导致对外部服务的绑定：

- `POSTGRES_PASSWORD`（默认 `postgres`）、`JUICEFS_POSTGRES_PASSWORD`（默认 `juicefs-postgres`）
- `S3_ENDPOINT`（默认 `http://minio:9000`）、`MINIO_ROOT_USER`、`MINIO_ROOT_PASSWORD`
- `WEAVIATE_HOST_DOMAIN`、`NEO4J_DOMAIN`、`WEAVIATE_HOST_PORT` 等
