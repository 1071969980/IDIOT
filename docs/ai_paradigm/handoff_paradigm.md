# handoff（快照）编写范式（跨项目复用）

## 1. handoff 是什么、不是什么

- **是**：协作的**工作入口**。回答三个问题——现在在哪、下一步是什么、一个新会话怎么接手。
- **场景**：换会话与上下文压缩是常态断点；断点之后，先前对话里的一切都不复存在——快照是断点处唯一随身携带的关键文档。
- **位置**：项目的临时文档文件夹
## 2. 如何思考一次跨断点的信息传递（本文主体）

写快照，本质上是一次「把信息送过断点」的设计——送的人此刻在场，收的人不在场，且没有问答回合。下面是这套思考的步骤。它负责**生成内容**；文档长什么样，是这些步骤算出来的结果，不是出发点。

**第一步：把断点摆在眼前，清点对面手里有什么。**
对面那位（明天的你，或一个全新会话）手里有：全部持久工件——代码、提交历史、环境本身。他没有：本次对话里的一切，尤其是所有**没有写下来**的东西——临时的判断、取舍的理由、已排除的方向、双方「不言自明」的默契。所以第一问不是「我该写什么」，而是：**哪些东西只在我脑子里，断点一过就没了？**

**第二步：把「恢复完成」定义成一个动作，而不是一种知识状态。**
恢复完成的判据不是「他了解了项目」，而是「他能正确地说出并能执行下一步」。这一步定义得越具体，后面的取舍越轻松。如果你写不出一个具体的下一步，说明工作本身停在一个含糊处——先想清它，那才是真问题。

**第三步：自己从对面走一遍，沿途收集卡点。**
带着零上下文，想象自己执行那个「下一步」：第一步会想查什么？哪里会误解？哪里有更省事的岔路其实是错的？每个卡点就是一条必须传递的信息。这是**生成**内容的方法，不是检查表——它自动适配项目大小：卡点多就写得多，卡点少就写得少。

**第四步：每条卡点先问「别处有没有」，再决定怎么写。**
- 别处有（某个文件、某条命令）→ 写成**指针**，不复述。复述会制造第二个权威，而且它会随工件更新而过时。
- 别处没有 → 这就是快照的核心内容。再追一句「为什么别处没有」：多半因为它是**进行中的状态**或**此刻的判断**——只存在于会话里，断点即灭。


**第五步：给每条信息一个「可核对的形态」。**
对面无法追问——快照是一次性传递，没有问答回合。这是它与对话的根本区别：对话里模糊可以当场澄清，快照里模糊不可修复。所以形容词（「基本完成」「一切正常」）等于没传；能变数字的变数字，能变命令的变命令，能变编号的变编号。
另有一层作用：快照写在断点之前、读在断点之后，中间世界可能已经动过。可核对的形态（一组基线数字、一条验证命令）也是他**发现「这份快照已经过时」的唯一途径**。

**第六步：按他的需要排序，不按你的分类。**
他要先知道「这是什么、走到哪了」，才能读懂「下一步为什么是它」；要先能核对「世界是否仍如描述」，才能安全动手。自然顺序是：定位 → 位置（含未落账）→ 方向（已裁与待裁）→ 核对手段 → 陷阱。你的分类（设计／计划／环境／纪律）是你的检索结构，不是他的阅读结构。

**第七步：把「现在该做什么」立成脊，其余内容挂在它上面。**
全篇的组织轴不是分类，而是那条恢复路径。写完之后只问一句：**一个陌生人从第一行读到能开工，路上有没有断点？**

## 3. 思考的产物：文档的形态（格式规范）

格式规范是上述七步算出的默认形态——照它写不会错。项目有自己的理由时可按需增删，但两件事恒定：**入口路径必须第一屏且有序**，**其余各节供跳查、无阅读顺序**。

**入口路径（第一节）**：有序的最短路径，三步上下——读什么（本档＋关键文件，带编号）→ 验什么（复跑哪条验证链、期望什么数字）→ 干什么（指向计划节哪一项；哪些决定已裁、哪些待裁问题开工前先呈报）。终点是「可以开始干活」；走到终点仍未恢复生产状态，就说明快照缺了内容——缺什么补什么。

**资料节（其余各节，默认集如下，按需取用）**：

| 节 | 内容要点 |
|---|---|
| 事件定位与进展 | 一段话讲清这是什么；已完成工作只留最近几个与里程碑级（一行一个、带交付物指针） |
| 进行中与未落账 | 当前工作停在哪一步；哪些已入账（带编号）、哪些没有；有无未落账的改动；已呈报未裁的事项——断点后最先要接的就是它 |
| 权威与状态 | 各工件的位置指针；当前基线的可复跑数字 |
| 计划 | 按序编号的下一步；每项带目标、已知约束（含必须遵守的既有决定编号）、待裁问题（「开工前先呈报」显式标出） |
| 环境与复验手段 | 零摸索跑通验证的清单；已知环境坑与「此路不通」的替代路径（软件域即具体命令） |
| 协作方式 | 指向范式文档；仅列本项目特有纪律的一句话提醒，不复制范式语义 |
| 易忘备忘 | 反复踩过的坑，口诀化、带出处编号，供同类错误再犯前快速对上 |

入口路径与资料节是两种东西：资料可以按需查阅，入口必须第一屏、且有序——一份只有资料没有入口的快照，接手者得先自己发明一个读法。

写完自查三条：

- 没读过任何聊天记录的人，能否只凭这篇复工？
- 有没有哪句是没有核对形态的形容词？
- 有没有哪段是在复述工件里已有的内容？

## 4. 生命周期

- **创建**：根据用户指令或任务阶段性完成时
- **刷新**：每个闭环收尾时，刷新是**改写**，不是追加——快照没有历史；旧状态覆盖掉，只留仍活的内容。刷完自检：旧内容是否都已入账？
- **弃**：事件的复杂度大幅收敛前没有新的缺口时

## 5. 快速起步

最小可用快照＝一条入口路径＋几段资料即可开工。宁短勿全——接手者缺什么会顺着指针找到；快照里唯一不能缺的，是**那条路径**、**指针本身**与**基线数字**。
