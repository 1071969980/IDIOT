# 分布式锁使用规范

本项目通过 Redis 实现分布式锁，用于保护并发安全的临界区操作。所有锁名称集中在 `api/redis/lock_names.py` 中管理。

## 核心组件

| 组件 | 用途 |
|------|------|
| `RedisDistributedLock` | 上下文管理器，手动控制锁的获取/释放 |
| `distributed_lock` | 装饰器，自动为 async 函数加锁 |
| `LockNames` | 锁名称注册表，所有锁名在此集中定义 |

```python
from api.redis.distributed_lock import RedisDistributedLock, distributed_lock
from api.redis.lock_names import LockNames
```

## 锁命名管理

**禁止在业务代码中硬编码锁名字符串**。所有锁名必须在 `LockNames` 中定义：

- **静态锁名**：类属性，用于全局唯一的锁（如初始化）
- **动态锁名**：`@classmethod`，接受参数生成锁名（如按资源 ID 隔离）

```python
# api/redis/lock_names.py

class LockNames:
    # 静态锁名
    INIT_POSTGRES_DB: str = "init_postgres_db"

    # 动态锁名
    @classmethod
    def user_pod_schedule(cls, user_id: str | UUID) -> str:
        return f"user_pod_schedule:{user_id}"
```

新增锁名时，在 `LockNames` 中添加对应的属性或方法即可。

## 使用方式

### 方式一：装饰器（推荐用于函数级加锁）

适用于整个函数体都需要锁保护的场景。

**静态 key：**

```python
@distributed_lock(LockNames.INIT_POSTGRES_DB)
async def init_db():
    ...
```

**动态 key：**

通过 lambda 从被装饰函数的参数中提取值生成锁名：

```python
@distributed_lock(lambda bound: LockNames.user_pod_schedule(bound.arguments['user_id']), timeout=300)
async def create_or_start_user_pod(user_id: UUID | str):
    ...
```

`bound` 是 `inspect.BoundArguments` 对象，通过 `bound.arguments['参数名']` 访问参数值。

### 方式二：上下文管理器（推荐用于方法内局部加锁）

适用于只需要保护函数内部部分逻辑的场景，粒度更细。

```python
async def create_todo(self, todo: TodoModel) -> str:
    lock_key = LockNames.task_storage_snapshot(self.task_id)
    async with RedisDistributedLock(lock_key):
        snapshot = await self._get_snapshot()
        # ... read-modify-write 操作
        await self._save_snapshot(snapshot)
    return todo.title
```

### 方式三：contextmanager + 内部方法拆分

当锁内逻辑较复杂时，可将受保护逻辑拆到 `_locked` 后缀的内部方法，保持外层方法简洁：

```python
async def create_todo(self, todo: TodoModel) -> str:
    lock_key = LockNames.task_storage_snapshot(self.task_id)
    async with RedisDistributedLock(lock_key):
        return await self._create_todo_locked(todo)

async def _create_todo_locked(self, todo: TodoModel) -> str:
    snapshot = await self._get_snapshot()
    # ... 业务逻辑
```

## 常见参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `timeout` | 30s | 锁超时时间，超时后自动释放 |
| `auto_renewal` | True | 是否自动续期（看门狗机制） |
| `allow_multi_lock` | False | 是否允许同一上下文中持有多个锁 |

对于耗时较长的操作（如 K8s Pod 创建），应适当增大 `timeout`：

```python
@distributed_lock(lambda bound: LockNames.user_pod_schedule(...), timeout=300)
```
